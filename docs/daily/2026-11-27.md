人为引起的气候变化的大部分焦点都集中在化石燃料上，它们造成了我们的大部分问题。但土地利用变化也是这个故事的一个重要组成部分，约占历史CO 2 排放总量的三分之一。森林砍伐在这里发挥着重要作用，但排干湿地等做法也起到了重要作用。要弄清楚我们消灭湿地的历史究竟在多大程度上导致了变暖，很难弄清楚。但由于测量了当今幸存湿地排放量的新数据来源，有可能给出更好的数字。

麻省理工学院的 Jevan Yu 领导的一项新研究重点关注泥炭地——沼泽和沼泽等环境，有机物在这些环境中积累成厚厚的物质层。研究人员指出，这些巨大的泥炭储量中蕴藏着约 6000 亿吨碳，这比世界上所有活植被中所能找到的碳还要多。

由于这些区域永久被淹没，水中的氧气很快就会耗尽，将所有有机物的腐烂工作留给了厌氧细菌，它们的工作速度要慢得多，并且不会消化所有东西。因此，在泥炭地中，有机碳并没有转化为好氧细菌释放的CO 2 气体，而是其中一部分逐渐转化为甲烷气体。甲烷是一种比CO 2 本身更有效的温室气体，最终会被氧化成CO 2 。这意味着泥炭地需要进行一些权衡——泥炭地中的大部分碳都被排除在大气之外，但逸出的碳却以甲烷的形式逸出。

许多泥炭地因挖沟渠而被排干，使水流出，以将土地重新用于农业或其他用途。这会降低水位，为暴露的泥炭提供氧气，并敲响需氧细菌的晚餐铃声。甲烷排放量下降，而CO 2 排放量大幅上升。

研究人员利用最近测量泥炭地气体排放的研究建立了一个全球模型，估算水位下降时 CO 2 和甲烷的释放量。这两种气体对给定的水位下降的反应不同，尤其是 CO 2 根据沼泽所在的世界位置的不同，反应也不同。该团队利用历史泥炭地排水造成的水位变化重建，从 1800 年开始运行他们的模型。

表示 CO 2 和甲烷变化对气候影响的最简单方法是计算地球能源预算的变化，换句话说，是温室效应的强度。他们计算出，到 2020 年，CO 2 排放对地球表面的总影响约为 +83 毫瓦，而甲烷排放减少则对每平方米产生约 -9 毫瓦，总影响为 +73 毫瓦。这占人类造成的地球能源预算变化总量的 2.7%。 （考虑到所有这些数字的误差线，它是 1.8% - 3.6%。）

我已经自我托管东西很多年了。有时我对此非常热衷，不断尝试新软件并修补我的基础设施。但到了某个时候，这种热情就消退了一些。我从未真正停止过自托管，但我越来越不愿意尝试新事物。维持已有的跑步对我来说就足够了。然而，在过去的几个月里，我发现自己对自托管再次变得越来越兴奋。而且，有点讽刺的是，人工智能是造成这种情况的一个重要原因。减少摩擦 我的大部分基础设施配置都位于 Git 存储库中，主要以 Docker Compose 文件、脚本和其他配置文件的形式存在。这使得使用人工智能编码代理在我的基础设施上工作成为可能，就像在任何其他软件项目上工作一样。每当我想尝试新服务、调整现有配置或自动化某些操作时，我现在都可以轻松完成。在过去，我有时会推迟某些更改，只是因为我不想花一个晚上阅读更改日志和文档或解决问题。并不是说我以前不能做这些事情。但通常情况下，所需的努力对我来说并不值得。现在，即使是相对自发的想法也常常最终成为现实。尝试我总是觉得有趣的事情还有一些技术我一直觉得很有趣，但从来没有觉得自己有足够的知识来真正利用它们。 NixOS 就是一个很好的例子。我一直喜欢以声明方式配置整个系统的想法；我什至在 Linux 蜜月阶段在我的笔记本电脑上使用了它。但按照我想要的方式配置所有内容是一个很大的障碍。在人工智能的帮助下，我现在在我的家庭服务器上更广泛地使用 NixOS。对于我的 VPS 基础设施，我也开始构建自己的基于 Debian 的 bootc 映像（在考虑了一段时间之后）。我觉得在 Git 存储库中定义我的整个操作系统配置并自动构建可启动的容器映像非常酷。但这也是我以前可能不会投入足够时间独自工作的事情。即使有了AI的帮助，几个月前设置的时候我还是花了半天时间。如果没有人工智能，我可能至少需要一周的时间。人工智能让尝试不熟悉的技术变得更加容易。在开始之前，我不一定需要了解每一个小细节。我可以一路学习，提出问题，逐步完善我的配置。几乎所有事情都实现自动化 我最终还成功做到了自动化基础架构的大部分构建、更新和部署流程。自托管涉及的许多工作并不是特别令人兴奋。跟踪新版本、更新容器镜像标签、构建镜像和部署配置更改都是需要定期完成的事情。我仍然记得更新服务的样子：在我的笔记本电脑上更改版本并调整 Docker Compose 文件，将更改推送到 Git 远程，通过 SSH 连接到服务器，拉取更改，最后部署它们。现在，一次 Git 推送就足够了。如果甚至有必要推动的话。有了 Renovate，我不再需要主动跟踪大多数软件更新。它为我创建拉取请求，通常，我需要做的就是审查和合并它们。我什至可以坐在沙发上用手机做这件事。推送更改或合并拉取请求会触发相应的 GitHub Actions 或 Forgejo Actions 工作流程，这些工作流程负责构建和部署所有内容。当然，这并没有什么特别突破性的。 DevOps 已经存在很长时间了，这些自动化工具都不需要人工智能。但人工智能帮助我以一种我以前不需要的方式将所有这些部分组合在一起
